# Яндекс Метрика и связь с продажами

Российская адаптация `analytics` из Marketing Skills Кори Хайенса. Версия 3.0.0.

Прочитать [общий российский контекст](../ru-context.md) и имеющиеся данные этого проекта. Задать только недостающие существенные вопросы по 1–3, с вариантами, возможностью своего ответа и выбора моделью. Если пользователь поручил решить самостоятельно — продолжить с обозначенными гипотезами.

## Входные данные

Бизнес-цель, сайт/приложение, путь клиента, доступные кабинеты и CRM, события и идентификаторы.

## Порядок работы

1. Построить путь до выручки и выбрать источник истины для каждого этапа: сайт, подтверждение формы, CRM, заказ, платёж.
2. Составить события: просмотр, начало формы, успешная заявка, переход в мессенджер, квалификация, заказ, подтверждённая оплата. Цели Метрики использовать с учётом их реальных условий срабатывания.
3. Зафиксировать единое именование и параметры: source, campaign, landing, region, lead_id/order_id там, где допустимо. Не отправлять ФИО, телефоны и email в URL, имена целей и открытые параметры.
4. Спроектировать UTM и передачу источника в CRM. Для товаров согласовать ecommerce-события с разработчиком и конкретной CMS.
5. Проверить успешный и неуспешный сценарии на телефоне: событие один раз, сумма и валюта верны, перезагрузка не дублирует заказ, тестовые данные отделены.
6. Описать расхождения и ограничения: блокировка счётчика, переход между устройствами, звонки и мессенджеры. Настроить отчёт по качеству лидов, а не только по кнопкам.

## Результат

План измерения: событие → условие → источник → параметры → проверка; UTM-словарь; воронка и список доступов для внедрения.

## Проверка качества

Тестовый клик не выдан за внедрённую интеграцию. «Оплата» срабатывает по подтверждению, а не по возврату на страницу.
