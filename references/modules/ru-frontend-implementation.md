# Реализация интерфейса и скорость

Прочитать соответствующий модуль references/core/sites.md от корня системы, текущие материалы проекта и ограничения пользователя. Использовать только доступные инструменты и профильные навыки.

## Процедура

Прочитать текущий проект, компоненты и конфигурацию. Выбрать минимальное подходящее решение; для простой страницы не вводить новый фреймворк без необходимости.
Разделить данные, состояние и отображение. Сетевой запрос не запускать случайно при каждом рендере. Проверять загрузку, пустое состояние, ошибку, частичные данные и успех.
Сохранять семантику, labels, фокус и порядок клавиатуры. Длинный русский текст проверять на узкой и широкой раскладке. Состояния отправки подтверждать сервером.
Для производительности сначала измерить проблему. Убирать ненужные загрузки и повторные вычисления, оптимизировать медиа и размеры; мемоизацию применять по наблюдаемой причине.
Проверить главный путь через существующий браузерный инструмент по ru-webapp-testing. Исходный код не заменяет визуальную проверку. Для доступности и дизайна использовать существующие модули 51–54 без второго дублирующего аудита.

## Результат и проверка

Выдать порученный результат и подтверждённые проверки. Обозначить нерешённые дефекты и недоступные проверки. При существенном исправлении сохранить правило в пределах проекта. Происхождение методик — [NOTICE.md](../../NOTICE.md).
