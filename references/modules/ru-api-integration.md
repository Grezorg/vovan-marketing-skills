# Надёжные интеграции API

Прочитать соответствующий модуль references/core/software.md от корня системы, текущие материалы проекта и ограничения пользователя. Использовать только доступные инструменты и профильные навыки.

## Процедура

Проверить текущую официальную документацию, доступ аккаунта, схему запроса и ответа. Не угадывать endpoint или считать наличие ключа подтверждением права на операцию.
Разделить публичные настройки и секреты. Проверять входные данные и ответ; ограничить таймаут, размер и число повторов. Соблюдать лимиты сервиса.
Для операций с побочным эффектом использовать ключ идемпотентности или собственную запись состояния. После таймаута не повторять платёж/заказ вслепую; сначала выяснить итог.
Вебхук проверять по официальной схеме подписи и защите от повторной доставки. Сохранять требуемое исходное тело только в рамках обработки, не публиковать его.
Для долгой генерации различать принятие, обработку, готовность, скачивание и доставку. Проверять реальный файл и тип содержимого.
Тестировать положительный путь, отказ авторизации, лимит, таймаут и некорректный ответ. Mock подтверждает обработку, но не работу настоящего сервиса.

## Результат и проверка

Выдать порученный результат и подтверждённые проверки. Обозначить нерешённые дефекты и недоступные проверки. При существенном исправлении сохранить правило в пределах проекта. Происхождение методик — [NOTICE.md](../../NOTICE.md).
