# Запуск проверок через Playwright CLI

Применять вместе с [проверкой сайта и форм](../modules/ru-webapp-testing.md). Этот файл описывает способ исполнения; общую проверку формы не дублировать.

## Выбрать разрешённый инструмент

Сначала прочитать инструкции доступного браузерного инструмента и использовать назначенный средой способ управления. CLI применять там, где он доступен и разрешён: в проекте пользователя или тестовом исполнителе. Он не заменяет правила доступа к браузеру и не переносит авторизацию из ChatGPT автоматически.

Проверить package.json/lockfile и `npx playwright-cli --help`. При отсутствии пакета установить @playwright/cli в рамках разрешённой задачи и текущей среды; не считать включение этой инструкции установленным браузером. Для постоянных регрессионных проверок использовать существующий Playwright Test, когда он уже есть.

## Открыть и осмотреть

Использовать реальный разрешённый HTTPS URL или адрес, выданный штатным предпросмотром. Для вымышленной локальной формы использовать штатный HTTP-сервер доступной среды; не обходить блокировку file:// или запрет сетевых сокетов.

При поддерживаемой установленной версии:

```bash
npx playwright-cli -s=qa open https://example.com
npx playwright-cli -s=qa snapshot
```

Следующие команды составлять по полученному снимку DOM. Примеры ссылок e5/e9 в чужой документации не являются элементами исследуемой страницы. После перехода повторно осматривать состояние. Для кода выбирать наблюдённые роли, labels и однозначные селекторы.

## Сформулировать проверяемое ожидание

Для тестовой формы с наблюдёнными полями и кнопкой пример команды:

```bash
npx playwright-cli -s=qa run-code "async page => { await page.getByLabel('Имя', {exact:true}).fill('Тест'); await page.getByRole('button', {name:'Рассчитать', exact:true}).click(); return await page.getByRole('status').innerText(); }"
```

Это образец синтаксиса, не готовый тест любого сайта. Проверять результат сравнением с ожидаемым значением или assertion; завершившаяся команда сама по себе не означает успешного сценария. Для ожидания использовать видимый конкретный результат и ограниченный таймаут.

При пакетном сценарии проверить результат значимого шага перед зависимым действием. Если немедленный переход не наблюдается, получить свежий DOM и дождаться условия; не объявлять дефект только по устаревшему снимку.

## Отделить уровни доказательств

| Уровень | Что подтверждает |
|---|---|
| Вымышленная форма | CLI открыл браузер, взаимодействовал с полями и выполнил проверку |
| Mock сервера | Клиент обработал заданный ответ |
| Настоящий сайт | Наблюдённое поведение конкретной версии и сценария |
| Получение заявки | Отдельно проверенная запись/подтверждение в целевой системе |

Если обязательное согласие блокирует отправку, такой тест не подтверждает проверку длины телефона сервером. Для проверки успешной доставки использовать разрешённый тестовый контур/реквизиты и уже данное разрешение на внешнее действие.

Секретные заголовки, cookie, storage-state и профиль хранить вне публикуемых файлов и логов. Скриншоты с персональными данными использовать только для внутренней проверки; не включать их в общедоступное доказательство.

Закрыть созданную тестовую сессию и удалить временные файлы доступа после проверки:

```bash
npx playwright-cli -s=qa close
```

Описать сценарии, ожидание, наблюдение, статус и точные пределы. Не объявлять проверенной мобильную версию, Safari или настоящую отправку по одному тесту Chromium. Версии и подтверждённый пробный запуск: [происхождение](sources.json).
