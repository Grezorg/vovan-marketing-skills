# Проверяемая память проекта
Хранить компактные записи: факты, решения, исправления, уроки, открытые задачи. Указывать проект, дату, источник и степень подтверждения. Не переносить правила одного проекта в другой без основания.
Перед продолжением прочитать актуальный документ проекта или память OS. Видимое состояние и текущая версия файла важнее старой записи. При конфликте сохранить новое подтверждённое решение и отметить прежнее как заменённое.
Использовать `scripts/state.py show`, `checkpoint` и `remember` с JSON через stdin. Локальная запись ещё не означает постоянное сохранение: для состояния в навыке прочитать навык создания навыков, проверить изменения и синхронизировать его репозиторий. Для документов проекта использовать его постоянное хранилище и профильный навык.
Сохранять только нужные для работы сведения, без токенов, паролей и полного содержимого личных сообщений. При словах «запомни» выполнить сохранение и сообщить его реальный результат. Не обещать встроенную глобальную память ChatGPT, если была записана только память OS.

## Паспорт и передача

Для многоэтапной работы использовать [паспорт проекта](../project-context-template.md) и [передачу между чатами](../project-transfer-template.md). Создавать их в постоянном хранилище конкретного проекта, обновлять существующие документы по их идентификаторам. Для уже связанного с Git проекта использовать его репозиторий. В ChatGPT использовать доступное постоянное хранилище файлов. Сначала читать актуальные документы, затем проверять нужные ссылки и версии. При недоступном хранилище обозначить локальный предел сохранения.

Записи state.py использовать как компактный индекс и контрольную точку со ссылкой source на паспорт. Готовые файлы и подробные журналы хранить по ссылкам в проекте. Соблюдать границы разрешения из актуального поручения при восстановлении контекста.

## Сохранность материалов

Отмечать назначение файлов как временные, рабочие исходники или итоговые результаты. Сохранять окончательные файлы и дорого воспроизводимые исходники в постоянное хранилище до очистки временного. В паспорт вносить постоянный идентификатор и версию, при необходимости размер и контрольную сумму.

При недоступном локальном файле сначала восстановить его из постоянного хранилища и проверить соответствие версии. Автоочистку по срокам включать лишь по отдельному поручению с явной областью удаления, защищёнными каталогами и предварительным списком кандидатов. Учитывать исходники, резервные копии и итоговые работы при защите от очистки.

Для резервирования проверить восстановление копии в отдельное место и читаемость либо работоспособность результата. Записывать дату и охват проверки. Существование копии подтверждает сохранение, успешное восстановление подтверждает пригодность резервирования.
