# Проверка возможностей перед работой

Применять перед внешним действием, генерацией, сохранением или при первом использовании зависимости. Повторять после смены среды, отказа или изменения доступа. Для обычного текста без внешних зависимостей достаточно продолжить задачу.

## Порядок

1. Из конечного результата выписать только необходимые возможности: чтение источника, генерация, озвучка, монтаж, постоянное сохранение, публикация.
2. Найти доступный инструмент и прочитать его текущую схему. Различать «есть в списке» и «проверен доступ»: по возможности сделать безопасный запрос статуса/чтения по назначению. Проверка не должна запускать генерацию, покупку, отправку или публикацию.
3. Зафиксировать для каждой зависимости состояние: доступ подтверждён; инструмент объявлен, доступ не проверен; недоступна; неизвестно. Указать наблюдение и время. Состояние одного аккаунта не переносить на другого.
4. Проверить расходы только доступным способом. «Бесплатный исходный код», подписка, бесплатная квота и оплачиваемый API — разные условия. Если баланс или цена недоступны, писать «неизвестно», не вычислять их из числа прежних роликов. При бюджете 0 ₽ не запускать операцию с неизвестными дополнительными списаниями.
5. Выбрать выполнимый результат и резервный путь. Показать пользователю лишь существенное ограничение, затем продолжить независимую работу.

## Формат внутренней записи

Возможность → инструмент → наблюдаемое состояние → источник/время → стоимость/квота → резервный путь. Не хранить секреты, токены, полное содержимое личных сообщений. Упоминание инструмента в тексте не является доказательством вызова.

## Примеры

- Есть монтаж и исходные видео, но нет генератора: собрать ролик из исходников, если это соответствует запросу.
- Нет озвучки: подготовить и проверить текст; не объявлять MP4 с голосом готовым.
- Есть готовый файл, публикация не разрешена: сохранить файл и подготовить упаковку.
- Нет постоянного хранилища: обозначить локальное сохранение и его предел.
- После таймаута публикации: сначала установить итог исходного запроса; не повторять вслепую.

Локальная команда scripts/doctor.py проверяет версию и наличие исполняемых программ. Она не подключается к сервисам, не читает ключи и не доказывает доступность API.
