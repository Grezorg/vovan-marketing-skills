# Данные, схемы и миграции

Прочитать соответствующий модуль references/core/software.md от корня системы, текущие материалы проекта и ограничения пользователя. Использовать только доступные инструменты и профильные навыки.

## Процедура

Изучить текущую схему, ограничения, объём, запросы и резервирование. Для Supabase прочитать его профильный навык; не делать неподтверждённые предположения о политиках доступа.
Задавать первичные ключи, уникальность бизнес-сущностей, обязательность и внешние связи. Время хранить с понятным часовым поясом. Для денег использовать точное представление.
Проверять принадлежность данных пользователю на сервере; клиентское скрытие не является защитой. Индексы выбирать по фактическим запросам и планам выполнения.
Миграцию разделять на добавление совместимого поля, перенос данных, переход приложения и удаление старого. Для опасной правки иметь проверенную резервную копию и способ возврата.
Проверить чтение/запись, уникальность, гонки и права в разрешённом тестовом контуре. Не удалять реальные данные как способ прохождения теста.

## Результат и проверка

Выдать порученный результат и подтверждённые проверки. Обозначить нерешённые дефекты и недоступные проверки. При существенном исправлении сохранить правило в пределах проекта. Происхождение методик — [NOTICE.md](../../NOTICE.md).
